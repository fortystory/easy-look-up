# 内容编写规范

`content/` 下的 JSON 文件是站点的全部内容。每个文件是一个**分组**，每个分组属于一个**类别**。

```
content/
├── go/          ← 类别，URL 是 /go
│   ├── basic-types.json
│   ├── control-flow.json
│   └── ...
├── stdlib/      ← 类别，URL 是 /stdlib
└── gin/         ← 类别，URL 是 /gin
```

## 文件格式

```json
{
  "id": "basic-types",
  "title": "基本类型与变量",
  "entries": [
    {
      "title": "整型",
      "description": "Go 的整型分有符号和无符号两族。不写位数就是 int。",
      "code": "var age int = 18\nfmt.Println(age)",
      "lang": "go",
      "notes": "整数溢出不会报错，会绕回变成负数。"
    }
  ]
}
```

### 分组字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 英文 slug，**必须和文件名去掉 .json 后一致** |
| `title` | ✅ | 中文标题，页面上显示 |
| `entries` | ✅ | 条目数组，不能为空 |

### 条目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 条目标题 |
| `description` | | 一到两句说明，讲**什么时候用**，不是复述代码在做什么 |
| `code` | | 代码片段，通常 3–8 行 |
| `lang` | 有 `code` 时必填 | 代码块的语言标识，目前都是 `"go"` |
| `notes` | | 常见坑。没有坑就写 `""` |
| `answer` | | 问答类条目的答案要点，一个字符串数组 |
| `expect_error` | | 可选，`true` 表示这段代码**故意编译不过**，教学点就是那个报错 |

**两种条目形态**：

- **代码片段型**：有 `code`（和 `lang`），说明在 `description`，坑在 `notes`。用于「某个语法怎么写」
- **问答型**：有 `answer`（数组），可以没有 `code`。用于「面试常问的某个问题」

每个条目至少有 `code` 或 `answer` 其中之一。一个分组里可以两种混着写，但同一个分组最好统一——全是问答型就没有「组合示例」这条要求。

问答型条目的 `answer` 是分点的答案，每点写一件事。页面上渲染成一个列表，可以直接扫读。

### 组合示例

每个分组的**最后一条**必须是组合示例，标题里带「组合示例」四个字。代码是一段**完整能跑的小程序**（以 `package main` 开头），把本分组学过的语法用在一起。

组合示例只能用到**本分组覆盖的语法**，不要引入别的分组的内容。

## 校验

改完内容必须跑：

```bash
python3 scripts/verify_content.py            # 校验全部类别
python3 scripts/verify_content.py go         # 只校验某个类别
```

它会检查：JSON 合法、字段齐全、`id` 与文件名一致、有组合示例、**每条代码都能被 Go 编译器接受**、完整程序能跑起来、gofmt 规范。

标了 `expect_error: true` 的条目反过来——必须编译失败。

## 写作要求

**代码**

- 片段控制在 3–8 行，只展示这一个语法点
- 片段里的每个变量都要被用到，否则 Go 会报 `declared and not used`（要演示这个报错就标 `expect_error`）
- 缩进用 **tab**（Go 惯例）
- gofmt 规范：`a := 1` 不是 `a:=1`，`var x int = 1` 不是 `var x int=1`
- 注释用**中文**（项目语言约定）

**说明**

- 讲**什么时候用这个**，不要复述代码语法
- 一到两句，别写段落
- 面向「Go 基础不多、正在学」的人

**坑**

- 只写真会踩的：编译报错、行为反直觉、和别的语言习惯冲突的
- 没有就写 `""`，不要凑数
- 一条坑说清楚一件事

**代码里的中文注释**

```go
var age int = 18   // 声明一个整型变量
```

## 类别与分组的边界

- `go` 类别 = **Go 语言本身**的语法
- `stdlib` 类别 = **Go 标准库**怎么用
- `gin` 类别 = **Gin 框架**怎么用

Gin 的内容不写进 `go` 类别，标准库也不写进 `go` 类别。

## 面试题类内容（问答型条目）

`interview-*` 类别是面试常问的问题，用问答型条目写。

**title** 写成**面试官会问的原话**，是个问句：

```json
"title": "goroutine 和线程有什么区别？"
```

**answer** 是分点的答案，3–6 点，每点一件事，一句话说清「是什么 / 为什么 / 怎么做」：

```json
"answer": [
	"goroutine 是 Go 运行时自己调度的轻量级执行单元，不是操作系统线程",
	"创建 goroutine 的初始栈只有 2KB，按需增长；线程的栈通常是 MB 级",
	"goroutine 阻塞时运行时会把对应的 P 让给别的 goroutine，不占着线程",
	"Go 1.14 之后 goroutine 可以被抢占，长时间计算不会卡住整个程序"
]
```

**notes** 写「面试官接下来会追问什么」和「常见的错误回答」：

```json
"notes": "常见追问：GMP 是什么？goroutine 泄露怎么排查？——第一个问题接着问调度器，第二个用 pprof 的 goroutine 视图看。"
```

**code** 有必要的就配一小段示例（必须能编译）；纯概念题可以不写这一项。

**写法要求**

- 答案是**要点式**的，不要写成一大段散文——面试时是要能扫读的
- 不要写「A 就是 B」这种同义反复，每点都要有信息量
- 涉及具体数字（默认栈大小、端口、超时时间、版本差异）要写准确；不确定的别写
- 有版本差异的（Go 1.18 泛型、Go 1.22 循环变量、Go 1.25 等等）要点明版本
- 一个分组里的问题要有明确的范围，不要和别的分组重复
