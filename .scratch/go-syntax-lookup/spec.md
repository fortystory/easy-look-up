# Go 语法速查站

## Problem Statement

一个正在学 Go 和 Gin 的开发者，在写代码时常常记不住某个语法的确切写法——知道大概形状，但不确定细节，比如 `slice` 截取的下标含义、`map` 遍历时那个 `, ok` 到底在判什么、`for range` 里拿到的 key 是什么类型。

现有的查证方式都不顺手：翻官方文档要跳转多层页面、读长篇教程要看掉上下文、搜索引擎的结果被无关内容淹没、自己攒的笔记散落在不同地方且没有高亮。

他需要的是一个能随手打开、按主题定位、直接复制走的速查页。

## Solution

一个只读的代码速查网站。

首页列出所有可查阅的类别。v1 有三个：`Go 语言`（语法本身）、`Go 标准库`、`Gin 框架`。点进任一类别得到一个详情页，页内按主题分成若干分组（基本类型与变量、条件分支、循环、切片、map、结构体与方法、函数、错误处理、接口、指针、泛型、并发、包与模块、常见错误……），每个分组下是若干条目。每条内容由标题、一到两句说明、和一段带语法高亮的代码组成，代码可以一键复制。

详情页顶部有一个搜索框，输入即时过滤条目；过滤后不再有匹配内容的分组自动隐藏。每个分组末尾还有一条「组合示例」，把该分组的语法拼成一个能直接跑的完整小程序。

页面支持亮色和暗色两套主题，跟随系统偏好，也可以手动切换并记住选择。

## User Stories

1. As a Go 学习者, I want 在首页看到所有可查阅的类别, so that 我知道这个站有什么可查的
2. As a Go 学习者, I want 点进 Go 类别看到按主题分组的全部语法, so that 我能按记忆里的主题定位
3. As a Go 学习者, I want 每个分组的所有条目默认全部展开, so that 我可以直接用浏览器自带的查找功能定位而不必逐个点开
4. As a Go 学习者, I want 页面顶部有一排分组锚点, so that 我能一键跳到想看的分组
5. As a Go 学习者, I want 每条内容除了代码还有标题和说明, so that 我知道这个语法什么时候该用，而不只是看到代码的形状
6. As a Go 学习者, I want 代码带语法高亮, so that 我能一眼分清关键字、类型、字符串和注释
7. As a Go 学习者, I want 一键复制代码, so that 我能直接粘贴进编辑器试
8. As a Go 学习者, I want 搜索框输入即时过滤条目, so that 我只记得零散关键词时也能快速找到
9. As a Go 学习者, I want 过滤后没有匹配内容的分组自动隐藏, so that 页面不会被空区块撑长
10. As a Go 学习者, I want 搜索同时匹配标题、说明和常见坑, so that 记不清标题但记得坑的时候也能搜到
11. As a Go 学习者, I want 搜索不匹配代码正文, so that 结果不会被代码里到处出现的常见词污染
12. As a Go 学习者, I want 每个分组末尾有一条组合示例, so that 我能看到这些语法合在一起是怎么用的
13. As a Go 学习者, I want 部分条目标注常见坑, so that 我不会踩别人已经踩过的坑
14. As a Go 学习者, I want 页面在手机上也能正常阅读, so that 我能在手机上查
15. As a Go 学习者, I want 页面加载很快, so that 我不会为了查一行语法而干等
16. As a 站点的维护者, I want 内容以 JSON 文件存放, so that 我加内容时不用改代码
17. As a 站点的维护者, I want 内容按分组分成多个文件, so that 我编辑某个分组时 git diff 的范围小、不容易冲突
18. As a 站点的维护者, I want 内容被编译进二进制, so that 部署只需要一个文件，也不会出现线上内容和本地不一致
19. As a 站点的维护者, I want 内容 JSON 写错时服务启动就失败并告诉我是哪个文件, so that 我不会上线一个内容缺了一半的站点
20. As a Go 学习者（同时是维护者）, I want 代码分成内容加载和页面渲染两个独立部分, so that 我能读懂每一部分在做什么
21. As a Go 学习者（同时是维护者）, I want 这两部分都能单独测试, so that 我改动时能立刻知道有没有破坏东西
22. As a Go 学习者（同时是维护者）, I want 一条命令就能把站跑起来, so that 我不用记启动参数
23. As a 站点的维护者, I want 加一条内容只需要按固定格式写一段 JSON, so that 内容的结构不会随时间慢慢漂移
24. As a Go 学习者, I want 站里除了 Go 语法还能查到标准库和 Gin 框架的用法, so that 我不用在几个网站之间来回跳
25. As a Go 学习者, I want 页面能切成暗色, so that 晚上查代码不刺眼
26. As a Go 学习者, I want 主题选择被记住, so that 下次打开还是我上次用的那个
27. As a Go 学习者, I want 不选主题时跟随系统, so that 不用我去设置
28. As a 站点的维护者, I want 内容里的代码示例能被自动验证确实能编译, so that 我不会发布一个跑不起来的例子
29. As a 站点的维护者, I want 有一段讲「初学者常踩的坑」的内容, so that 我踩过的坑别人不用再踩一遍

## Implementation Decisions

**技术栈与渲染模型**

- Go 1.27 + Gin + `html/template` 服务端渲染
- 语法高亮用 chroma 在服务端生成 HTML，不用前端高亮库
- chroma 用 **class 模式**（`WithClasses(true)`）而不是内联样式：内联样式把颜色写死在 HTML 里，暗色主题就接管不了。颜色由样式表按主题给 `.chroma .kd` 这类 class 上色
- 不引入前端框架、不引入构建步骤、不依赖 CDN。页面里的 JavaScript 只有主题切换、过滤、复制三处原生实现

**代码结构**

- 三个包：可执行入口包，加两个内部包
  - 内容包：负责加载内容目录、解析 JSON、组装出分类 / 分组 / 条目
  - 站点包：负责 HTTP 路由、handler、模板渲染
- 内容包不依赖站点包，反向不成立。内容包对外只暴露「加载出来的内容」和「加载函数」
- 模板和静态资源放在站点包内部（`internal/site/templates/`、`internal/site/static/`）并由站点包自己 `go:embed`。原因是 `go test` 跑测试时工作目录是**包目录**而不是仓库根——从磁盘按相对路径读模板在测试里会 panic（`pattern matches no files`），embed 进二进制则不受工作目录影响

**内容存储与加载**

- 内容以 JSON 文件存放，一个分组一个文件，放在内容目录下。目录结构是 `content/<类别>/<分组>.json`
- 内容目录用 `go:embed` 编译进二进制
- 内容在服务启动时一次性解析进内存，请求期间不再读文件
- 解析失败直接 panic 退出，错误信息必须指出是哪个文件出的问题
- 内容解析失败时不做降级、不跳过坏文件。宁可启动不了，也不要上线一个内容残缺的站
- 缺字段也要报错：`json.Unmarshal` 对缺失字段不报错，所以要自己校验

**路由**

- 根路径是类别页，列出所有类别
- 每个类别一条固定路由（`/go`、`/stdlib`、`/gin`）。不用 `/:category` 通配——那会和 `/static/*filepath` 抢路由，而且内容本来就编译进二进制，类别集合启动时已知
- 未知路径返回 404

**详情页布局**

- 一个类别一页
- 页内分组按内容文件里的数组顺序排列，顺序由内容作者控制
- 所有分组默认全部展开，不做折叠
- 页面顶部提供一组锚点导航，跳转到各分组
- 锚点用英文 slug

**前端过滤**

- 每条条目带一个 `data-search` 属性，内容是「标题 + 说明 + 答案要点 + 注意事项」拼成的可搜索文本
- 过滤在浏览器端完成，服务端不做任何过滤或搜索
- 匹配字段：标题、说明、答案要点、注意事项。不匹配代码正文
- 过滤后某个分组若一条都不剩，整个分组隐藏
- 不做命中关键词高亮

**内容模式**

每个分组文件是一个对象，字段为 `id`（英文 slug）、`title`（分组标题）、`entries`（条目数组）。每个条目含 `title`（标题）、`description`（一到两句说明）、`code`（代码块内容）、`lang`（代码块语言标识）、`notes`（常见坑，可选）、`expect_error`（可选，表示这段代码故意编译不过）。

模式长这样：

```json
{
  "id": "basic-types",
  "title": "基本类型与变量",
  "entries": [
    {
      "title": "整型与浮点型",
      "description": "Go 只有一组带符号整型，大小由位数决定。",
      "code": "var age int = 18\nvar pi float64 = 3.14",
      "lang": "go",
      "notes": ""
    }
  ]
}
```

问答型条目：

```json
{
  "id": "basics",
  "title": "Go 语言基础与常见陷阱",
  "entries": [
    {
      "title": "defer 什么时候执行？多个 defer 的顺序是怎样的？",
      "description": "defer 的执行时机是最容易想当然出错的地方。",
      "answer": [
        "return 语句先求值，再执行 defer，然后函数才真正返回",
        "同一个函数里的多个 defer 按后进先出（LIFO）执行",
        "正常 return、panic 展开都会执行 defer；os.Exit 和主 goroutine 直接结束不会"
      ],
      "notes": "常见追问：defer 里能不能改返回值？——看返回的是不是具名返回值。"
    }
  ]
}
```

**条目内容形态**

- 以语法片段为主：每条 3–8 行，只展示一个语法点
- 每个分组末尾追加一条「组合示例」条目，把该分组的语法拼成一个完整能跑的小程序
- 需要顶层函数或方法的条目写成完整小程序（`package main` 开头）——函数体内不允许声明具名函数和方法
- 覆盖三类「怎么写」的内容：
  - `go`：基本类型与变量、条件分支、循环、切片、map、结构体与方法、函数、错误处理、接口、指针、泛型、并发、包与模块、常见错误
  - `stdlib`：字符串与数值转换、排序与集合、文件与 I/O、时间、错误与格式化
  - `gin`：路由基础、请求绑定与校验、响应、中间件
- 覆盖七类「面试常问什么」的问答内容（`interview-*` 类别）：
  - `interview-go`：语言基础与陷阱、运行时与调度器、内存与 GC、并发原语、常用标准库、性能分析与优化、工具链与工程实践、语言设计与规范
  - `interview-concurrency`：性能指标与压测、高并发架构设计、并发问题排查、分布式并发、服务治理、高并发场景设计题
  - `interview-gin`：路由与中间件、请求解析与参数绑定、响应与错误处理、工程实践与性能
  - `interview-mysql`：索引与存储结构、事务与隔离级别、锁、查询优化、存储引擎与日志、高可用与运维
  - `interview-redis`：数据结构与底层实现、持久化与高可用、缓存设计与常见问题、分布式锁与一致性、性能与运维
  - `interview-web`：HTTP 协议、浏览器与页面渲染、Web 前端性能、Web 安全、API 设计与后端接口
  - `interview-network`：TCP 与可靠传输、Socket 与 IO 模型、DNS 与 TLS、网络问题排查

**两种条目形态**

- **代码片段型**：有 `code`（和 `lang`）。用在「某个语法怎么写」，每个分组末尾追加一条「组合示例」
- **问答型**：有 `answer`（字符串数组），可以没有 `code`。用在「面试常问的某个问题」，答案是分点的要点，页面上渲染成列表，可以直接扫读
- 一个条目至少有 `code` 或 `answer` 其中之一。同一个分组里统一用一种形态
- 问答型分组不要求「组合示例」条目

**内容的自动校验**

- 每个分组文件里的代码都要能被 Go 编译器接受。校验脚本把片段包成可编译单元，必要时补上用到的标准库 import
- 组合示例是完整小程序，除了编译还要实际跑一遍
- 标了 `expect_error` 的条目反过来——必须编译失败
- 校验脚本放在 `scripts/verify_content.py`，临时目录按进程隔离，可以并行跑

**交互与样式**

- 复制按钮用 `navigator.clipboard.writeText`，带 `execCommand` 兜底
- 手写单个 CSS 文件，不用框架、不用 CDN
- 亮色/暗色两套主题，颜色一律走 CSS 变量；`<html data-theme="light|dark">` 控制显式选择，不设时跟随系统 `prefers-color-scheme`
- 主题选择存在 `localStorage`，在 `<head>` 里有一段内联脚本尽早套用，避免刷新时闪白
- 端口 8080，一条命令启动

**工程约定**

- 代码风格策略：先直白——结构简单、少抽象，优先把功能跑通；之后单独用一轮重构练 idiomatic Go
- 断言库用标准库 `testing`，不引入第三方断言库
- Git 身份由开发者自行配置

## Testing Decisions

**好测试的标准**

- 只测 external behavior，不断言 implementation details
- 不测模板渲染的中间产物，只断言最终 HTML 里有没有该有的东西
- 前端 JavaScript 不做自动化测试；过滤的数据正确性由服务端在 `data-search` 属性里保证
- 内容文件的正确性由独立的校验脚本保证，不混进 Go 测试

**Seam 1：HTTP 请求层**

用 `httptest` 加 Gin 路由做端到端断言。

- 类别页：返回 200，响应体里能拿到类别的名称、链接和分组/条目数量
- 详情页：返回 200，响应体里能拿到分组标题、条目标题、说明、常见坑
- 详情页：响应体里有 chroma 的 class（证明高亮生效）且没有被转义
- 详情页：条目带 `data-search`（标题+说明+坑）和 `data-code`（复制用的原始代码）
- 详情页：页面含主题切换按钮和搜索框
- 静态资源：`/static/style.css` 和 `/static/app.js` 返回 200 且类型正确
- 样式表：包含亮色和暗色两套变量
- 未知路径：返回 404

**Seam 2：内容加载层**

直接调用内容加载函数。

- 合法 JSON：返回的分组数量、分组标题、条目数量与条目标题都正确
- 非法 JSON：返回 error，且错误信息里包含出错的文件名
- 类别目录不存在、目录里没有 JSON 文件：都返回 error
- 条目缺 title 或 code：返回 error
- 非 JSON 文件被跳过
- `List` 能列出所有类别且按字典序

**Seam 3：内容文件校验脚本**

`scripts/verify_content.py` 是独立于 Go 测试的一道关卡，跑在提交前。

- 每个分组文件的 JSON 合法、字段齐全、`id` 与文件名一致、有组合示例
- 每条代码都能被 Go 编译器接受，组合示例还要能实际跑起来
- 标了 `expect_error` 的条目必须编译失败
- gofmt 规范

**第三方库**

测试只用标准库。校验脚本用 Python 标准库。

**Prior art**

仓库起初为空，没有既有测试可参照。HTTP 层的测试按 Go 社区 `httptest` 的标准写法来。

## Out of Scope

- 内容编辑界面、后台管理、任何形式的写操作
- 数据库、用户账号、登录
- 服务端搜索、搜索索引。v1 的过滤完全在浏览器端
- 前端 JavaScript 的自动化测试
- 键盘快捷键面板、快捷键导航
- 部署配置（Docker、CI 等）。v1 的交付方式是本地 `go run .`
- 用户自定义配色、主题数量超过两套
- 分组级别的折叠/展开（v1 全部展开）

## Further Notes

**分工**

- 内容 JSON 由 agent 产出并自动校验，开发者负责评审内容质量：说法准不准、示例能不能跑
- 早期是「全部 Go 代码由开发者手写，agent 只评审」；随着范围扩大，样式、测试和内容批量产出改由 agent 承担，开发者保留对 Go 代码的最终决定权
- 评审输出格式：结论 + 必改项 + 建议项 + 顺带解释涉及的 Go 概念
- 评审时机：每个 red-green 循环之后评审一次——测试写错了，实现写得再对也是错的

**内容的产出节奏**

- 第一个分组「基本类型与变量」先作为内容形态的样板产出并评审，确认字段用法、组合示例的写法、注意事项怎么写之后，再按同一形态批量补齐
- 批量产出用并行 subagent，每个 agent 只写一个分组文件，写完自己跑校验脚本到全绿
- 校验脚本的临时目录按进程隔离，多个 agent 可以并行校验

**Git 约定**

- 每个 ticket 一个分支，分支内允许多个 commit：测试、实现、重构分开提交
- 评审以分支与 `master` 的差异为固定点

**环境**

- Go 1.27.3，linux/amd64
- `gofmt` 可用；`golangci-lint`、`staticcheck`、`dlv`、`air` 未安装，是否引入由开发者决定
- git 身份已由开发者配置为仓库级（不动全局配置）

**已知取舍**

- 过滤在浏览器端做，意味着条目总量会随每次请求完整下发给客户端。当前规模下这不构成问题；如果将来内容规模上一个量级，需要重新设计成服务端搜索
- 内容编译进二进制，加一个类别要重新构建。这与「内容用 JSON 存放」的初衷有张力，但换来了单一二进制和内容与代码同版本
- Go 1.27 起方法可以自带类型参数，这是 1.18–1.26 没有的能力。内容按当前工具链的语义写
