# Go 语法速查站

## Problem Statement

一个正在学 Go 和 Gin 的开发者，在写代码时常常记不住某个语法的确切写法——知道大概形状，但不确定细节，比如 `slice` 截取的下标含义、`map` 遍历时那个 `, ok` 到底在判什么、`for range` 里拿到的 key 是什么类型。

现有的查证方式都不顺手：翻官方文档要跳转多层页面、读长篇教程要看掉上下文、搜索引擎的结果被无关内容淹没、自己攒的笔记散落在不同地方且没有高亮。

他需要的是一个能随手打开、按主题定位、直接复制走的速查页。

## Solution

一个只读的语法速查网站。

首页列出所有可查阅的类别，v1 只有一个：Go。点进 Go 得到一个详情页，页内按主题分成若干分组（基本类型与变量、条件分支、循环、切片、map、结构体与方法、函数、错误处理），每个分组下是若干条目。每条内容由标题、一到两句说明、和一段带语法高亮的代码组成，代码可以一键复制。

详情页顶部有一个搜索框，输入即时过滤条目；过滤后不再有匹配内容的分组自动隐藏。每个分组末尾还有一条「组合示例」，把该分组的语法拼成一个能直接跑的完整小程序。

## User Stories

1. As a Go 学习者, I want 在首页看到所有可查阅的类别, so that 我知道这个站有什么可查的
2. As a Go 学习者, I want 点进 Go 类别看到按主题分组的全部语法, so that 我能按记忆里的主题定位
3. As a Go 学习者, I want 每个分组的所有条目默认全部展开, so that 我可以直接用浏览器自带的查找功能定位而不必逐个点开
4. As a Go 学习者, I want 页面顶部有一排分组锚点, so that 我能一键跳到想看的分组
5. As a Go 学习者, I want 每条内容除了代码还有标题和说明, so that 我知道这个语法什么时候该用，而不只是看到代码的形状
6. As a Go 学习者, I want 代码带语法高亮, so that 我能一眼分清关键字、类型、字符串和注释
7. As a Go 学习者, I want 一键复制代码, so that 我能直接粘贴进编辑器试
8. As a Go 学习者, I want 搜索框输入即时过滤条目, so that 我只记得零散关键词时也能快速找到
9. As a Go 学习者, I want 过滤后没有匹配内容的分组自动隐藏, so that 页面不会被空区块撑长
10. As a Go 学习者, I want 搜索同时匹配标题、说明和常见坑, so that 记不清标题但记得坑的时候也能搜到
11. As a Go 学习者, I want 搜索不匹配代码正文, so that 结果不会被代码里到处出现的常见词污染
12. As a Go 学习者, I want 每个分组末尾有一条组合示例, so that 我能看到这些语法合在一起是怎么用的
13. As a Go 学习者, I want 部分条目标注常见坑, so that 我不会踩别人已经踩过的坑
14. As a Go 学习者, I want 页面在手机上也能正常阅读, so that 我能在手机上查
15. As a Go 学习者, I want 页面加载很快, so that 我不会为了查一行语法而干等
16. As a 站点的维护者, I want 内容以 JSON 文件存放, so that 我加内容时不用改代码
17. As a 站点的维护者, I want 内容按分组分成多个文件, so that 我编辑某个分组时 git diff 的范围小、不容易冲突
18. As a 站点的维护者, I want 内容被编译进二进制, so that 部署只需要一个文件，也不会出现线上内容和本地不一致
19. As a 站点的维护者, I want 内容 JSON 写错时服务启动就失败并告诉我是哪个文件, so that 我不会上线一个内容缺了一半的站点
20. As a Go 学习者（同时是维护者）, I want 代码分成内容加载和页面渲染两个独立部分, so that 我能读懂每一部分在做什么
21. As a Go 学习者（同时是维护者）, I want 这两部分都能单独测试, so that 我改动时能立刻知道有没有破坏东西
22. As a Go 学习者（同时是维护者）, I want 一条命令就能把站跑起来, so that 我不用记启动参数
23. As a 站点的维护者, I want 加一条内容只需要按固定格式写一段 JSON, so that 内容的结构不会随时间慢慢漂移

## Implementation Decisions

**技术栈与渲染模型**

- Go 1.27 + Gin + `html/template` 服务端渲染
- 语法高亮用 chroma 在服务端生成 HTML，不用前端高亮库
- 不引入前端框架、不引入构建步骤、不依赖 CDN。页面里的 JavaScript 只有过滤和复制两处原生实现

**代码结构**

- 三个包：可执行入口包，加两个内部包
  - 内容包：负责加载内容目录、解析 JSON、组装出分类 / 分组 / 条目
  - 站点包：负责 HTTP 路由、handler、模板渲染
- 内容包不依赖站点包，反向不成立。内容包对外只暴露「加载出来的内容」和「加载函数」

**内容存储与加载**

- 内容以 JSON 文件存放，一个分组一个文件，放在内容目录下
- 内容目录用 `go:embed` 编译进二进制
- 内容在服务启动时一次性解析进内存，请求期间不再读文件
- 解析失败直接 panic 退出，错误信息必须指出是哪个文件出的问题
- 内容解析失败时不做降级、不跳过坏文件。宁可启动不了，也不要上线一个内容残缺的站

**路由**

- 根路径是类别页，列出所有类别
- `/go` 是 Go 详情页。v1 只有这一个类别页路由，但路由与数据模型按「任意多个类别」设计，加新类别不改动结构
- 未知路径返回 404

**详情页布局**

- 一个类别一页
- 页内分组按内容文件里的数组顺序排列，顺序由内容作者控制
- 所有分组默认全部展开，不做折叠
- 页面顶部提供一组锚点导航，跳转到各分组
- 锚点用英文 slug

**前端过滤**

- 详情页内嵌一份 JSON payload，包含全部条目的可搜索字段
- 过滤在浏览器端完成，服务端不做任何过滤或搜索
- 匹配字段：标题、说明、注意事项。不匹配代码正文
- 过滤后某个分组若一条都不剩，整个分组隐藏
- 不做命中关键词高亮

**内容模式**

每个分组文件是一个对象，字段为 `id`（英文 slug）、`title`（分组标题）、`entries`（条目数组）。每个条目含 `title`（标题）、`description`（一到两句说明）、`code`（代码块内容）、`lang`（代码块语言标识）、`notes`（常见坑，可选）。

模式长这样：

```json
{
  "id": "basic-types",
  "title": "基本类型与变量",
  "entries": [
    {
      "title": "整型与浮点型",
      "description": "Go 只有一组带符号整型，大小由位数决定。",
      "code": "var age int = 18\nvar pi float64 = 3.14",
      "lang": "go",
      "notes": ""
    }
  ]
}
```

**条目内容形态**

- 以语法片段为主：每条 3–8 行，只展示一个语法点
- 每个分组末尾追加一条「组合示例」条目，把该分组的语法拼成一个完整能跑的小程序
- Go 类别 v1 覆盖 8 个分组：基本类型与变量、条件分支、循环、切片、map、结构体与方法、函数、错误处理

**交互与样式**

- 复制按钮用 `navigator.clipboard.writeText`，带 `execCommand` 兜底
- 手写单个 CSS 文件，不用框架。浅色配色，不做深色模式
- 端口 8080，一条命令启动

**工程约定**

- 代码风格策略：先直白——结构简单、少抽象，优先把功能跑通；之后单独用一轮重构练 idiomatic Go
- 断言库用标准库 `testing`，不引入第三方断言库
- Git 身份由开发者自行配置

## Testing Decisions

**好测试的标准**

- 只测 external behavior，不断言 implementation details
- 不测模板渲染的中间产物，只断言最终 HTML 里有没有该有的东西
- 前端 JavaScript 不做自动化测试；过滤和复制的数据正确性由服务端在 payload 里保证

**Seam 1：HTTP 请求层**

用 `httptest` 加 Gin 路由做端到端断言。

- 类别页：返回 200，响应体里能拿到 Go 类别的链接
- 详情页：返回 200，响应体里能拿到全部 8 个分组的标题
- 详情页：响应体里能拿到各分组下条目的标题
- 详情页：内嵌的过滤 payload 完整，包含全部条目
- 未知路径：返回 404

**Seam 2：内容加载层**

直接调用内容加载函数。

- 合法 JSON：返回的分组数量、分组标题、条目数量与条目标题都正确
- 非法 JSON：panic，且错误信息里包含出错的文件名

**第三方库**

无。测试只用标准库。

**Prior art**

仓库目前为空，没有既有测试可参照。HTTP 层的测试按 Go 社区 `httptest` 的标准写法来。

## Out of Scope

- Go 以外类别的具体内容。站点架构支持多类别，但 v1 只做 Go 语法
- Gin 框架本身的用法文档。它是学习这个项目的载体，不是这个项目的内容
- 内容编辑界面、后台管理、任何形式的写操作
- 数据库、用户账号、登录
- 服务端搜索、搜索索引。v1 的过滤完全在浏览器端
- 深色模式、主题切换
- 前端 JavaScript 的自动化测试
- 键盘快捷键面板、快捷键导航
- 部署配置（Docker、CI 等）。v1 的交付方式是本地 `go run .`

## Further Notes

**分工**

- 内容 JSON 由 agent 产出，开发者负责评审内容质量：说法准不准、示例能不能跑
- 全部 Go 代码由开发者手写。agent 负责内容产出和代码评审
- 评审输出格式：结论 + 必改项 + 建议项 + 顺带解释涉及的 Go 概念
- 评审时机：每个 red-green 循环之后评审一次——测试写错了，实现写得再对也是错的

**内容的产出节奏**

- 第一个分组「基本类型与变量」先作为内容形态的样板产出并评审，确认字段用法、组合示例的写法、注意事项怎么写之后，再按同一形态批量补齐其余 7 组

**Git 约定**

- 每个 ticket 一个分支，分支内允许多个 commit：测试、实现、重构分开提交
- 评审以分支与 `master` 的差异为固定点

**环境**

- Go 1.27.3，linux/amd64
- `gofmt` 可用；`golangci-lint`、`staticcheck`、`dlv`、`air` 未安装，是否引入由开发者决定
- git 的 `user.name` 和 `user.email` 当前未配置，由开发者自行设置

**已知取舍**

- 过滤在浏览器端做，意味着条目总量会随每次请求完整下发给客户端。当前 8 个分组、约百条条目的规模下这不构成问题；如果将来内容规模上一个量级，需要重新设计成服务端搜索
